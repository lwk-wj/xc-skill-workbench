# 可编辑仓库配置设计

## 目标

将设置页当前只读的“CLI 仓库”信息改为可编辑配置，并继续复用
`~/.xc-skills-config.json`，让桌面端和 `xc-skills` CLI 使用同一份参数。
保存成功后，桌面端立即切换到新配置并刷新中央仓库。

## 非目标

- 不检测或安装全局 `xc-skills` CLI。
- 不引入桌面端私有的第二份仓库配置。
- 不自动保存字段，不在用户输入过程中连接仓库。
- 不改动 Agent、自定义项目或资源安装行为。

## 可编辑参数

- `mode`：本地仓库或远程仓库。
- `repoPath`：本地仓库路径。
- `remoteUrl`：远程 Git 仓库 URL。
- `defaultBranch`：默认分支。
- `defaultGroups`：默认扫描分组；空数组表示全部分组。

切换仓库模式时保留非当前模式的仓库字段。例如从本地切到远程时不清空
`repoPath`，方便用户之后切回。

## 设置页交互

“CLI 仓库”区域改为独立表单：

- 仓库模式使用单选或分段控件。
- 本地模式显示仓库路径输入框和“选择文件夹”按钮；路径既可粘贴，也可通过
  Electron 目录选择器填写。
- 远程模式显示远程仓库 URL 输入框。
- 默认分支使用文本输入框。
- 默认分组使用支持新增选项的多选标签组件。
- 区域底部提供“保存并刷新”按钮。表单没有修改或正在保存时禁用按钮。
- 保存成功后保留设置弹窗，显示简短成功反馈；用户可以继续编辑其他设置。

## 保存与刷新流程

1. 渲染进程进行必填项和基础格式校验：
   - 本地模式要求 `repoPath` 非空。
   - 远程模式要求 `remoteUrl` 非空。
   - 两种模式都要求 `defaultBranch` 非空。
   - 默认分组去除首尾空白、空值和重复项。
2. 渲染进程通过类型化 IPC 提交完整候选配置。
3. 主进程使用 `xc-skills/core` 校验候选配置，并尝试解析候选仓库：
   - 本地模式验证路径可访问并能作为仓库源读取。
   - 远程模式验证 Git 仓库和分支可访问，允许正常更新分支缓存。
4. 主进程在候选仓库可用后写入 `~/.xc-skills-config.json`。
5. 写入成功后，`CoreService` 原子替换内存中的配置、选中分支和仓库源，并清空
   旧资源目录缓存。
6. 主进程返回已规范化配置和新的仓库视图。渲染进程刷新中央仓库资源与分支列表。

在验证或写入完成之前，当前运行中的配置保持不变。

## 组件与接口边界

### 渲染进程

新增 `RepositoryConfigForm.vue` 管理仓库表单、脏状态、加载状态和字段级错误，
`SettingsDialog.vue` 只负责加载初始配置和组合各设置区域。保存成功后通过事件
通知资源浏览器重新加载当前来源。

### Preload 与共享协议

新增两个受 schema 校验的接口：

- `repositories.chooseLocalPath()`：打开目录选择器并返回路径或 `null`。
- `repositories.updateConfig(config)`：验证、保存并返回规范化配置与仓库视图。

IPC 不接收任意文件路径写入请求，只允许更新固定的 XC Skills 配置文件。

### 主进程

`CoreService.updateConfig` 负责候选配置验证、仓库解析、持久化和内存状态切换。
目录选择继续使用主进程现有的 Electron `dialog.showOpenDialog` 能力。

## 错误处理

- 字段缺失时直接在对应表单项下提示，不发起 IPC。
- 本地路径不存在、不是可用仓库，或远程仓库/分支不可访问时，在仓库配置区域显示
  具体错误，并保留用户输入。
- 候选配置验证失败时不修改磁盘配置和当前内存配置。
- 写入失败时保留当前配置并记录本地日志。
- 成功保存后若资源重新渲染失败，保留已经验证并写入的新配置，显示可重试提示；
  用户可以点击中央仓库的刷新操作重试。

## 测试

- `CoreService` 单元测试覆盖候选仓库验证成功、验证失败不写入、写入后替换内存状态
  以及默认分组规范化。
- IPC 测试覆盖输入 schema、目录选择取消和错误序列化。
- Vue 组件测试覆盖模式切换、条件字段、本地目录选择、多选分组、脏状态、保存成功和
  保存失败。
- E2E 测试使用临时配置和本地 Git 仓库，验证保存后中央仓库立即显示新来源内容。
- 完成后运行完整测试、类型检查和生产构建。
