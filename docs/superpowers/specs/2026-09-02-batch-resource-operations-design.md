# 批量资源操作设计

## 背景与目标

当前资源列表只支持逐条安装、冻结、解冻和卸载。资源数量增多后，重复打开操作弹窗、选择目标并确认会造成明显的操作负担。

本次改造在不改变 Core 单资源操作契约的前提下，为资源列表增加批量选择和渲染层编排能力，支持：

- 中央仓库、第三方仓库中的批量安装。
- 项目和全局安装列表中的批量冻结、解冻和卸载。
- 严格的操作资格校验、统一预览、串行执行和可读的结果汇总。

批量更新不在本次范围内。后台任务中心、跨页面持续执行和已完成操作自动回滚也不在本次范围内。

## 设计原则

1. 单资源与批量操作共用同一套资格规则和底层 `plan`、`execute` 接口。
2. 对危险或含混的选择采取严格校验：任意一项不符合要求时，整个批量操作不可执行。
3. 所有计划先成功生成，再允许执行，避免执行到一半才发现可预见的冲突。
4. 执行按确定顺序串行进行；首次失败立即停止，保留此前已成功的结果。
5. 批量选择始终限定在用户当前可见的上下文，防止对隐藏资源误操作。

## 列表选择交互

`AssetList` 的每行左侧增加复选框。复选框点击不会触发详情抽屉，资源名称和描述区域仍保持原有的详情入口。

列表上方增加吸顶式批量工具栏，包含：

- 三态全选框：未选择、部分选择、当前筛选结果全部选择。
- 已选数量，例如“已选择 8 项”。
- 当前来源允许的批量操作按钮。
- 清空选择入口。

“全选”只选择当前搜索、分组、状态和 Agent 筛选后的全部资源。以下上下文变化会清空选择：

- 切换中央仓库、第三方仓库、全局或项目来源。
- 切换 Skills、Rules 或 Workflows。
- 修改搜索词或任一筛选条件。

中央仓库和第三方仓库只显示“批量安装”。项目和全局列表显示“批量冻结”“批量解冻”和“批量卸载”。按钮是否可用由全部已选资源的资格校验结果决定。

视觉继续采用当前浅色、蓝色强调的工业实用风格。批量工具栏使用轻量边框浮层并在列表滚动时保持可见，不改变资源正文密度。卸载使用危险色，冻结和解冻沿用现有蓝色操作体系。

## 操作资格模型

从 `AssetList` 中提取共享的纯函数模块，统一计算单资源可用操作和不可用原因。批量工具栏与单行按钮都消费这一结果。

资格规则如下：

| 操作 | 合法条件 | 典型不合法原因 |
| --- | --- | --- |
| 安装 | 来源为中央仓库或第三方仓库，且资源可进入计划阶段 | 资源无效、目标配置缺失 |
| 冻结 | 资源存在明确的受管安装位置，且当前未冻结 | 未迁移、已冻结、目标缺失 |
| 解冻 | 资源存在明确的受管安装位置，且当前已冻结 | 未冻结、安装记录缺失 |
| 卸载 | 资源存在明确的受管安装位置 | 安装位置未知、未迁移 |

当选中项中存在任一不合法资源时：

- 对应批量按钮不可执行。
- 工具栏或按钮提示展示不合法数量。
- 点击提示可查看资源名称和逐项原因。

严格资格校验只处理当前可观测状态。来源冲突、目标占用、迁移要求等需要 Core 参与判断的错误在计划阶段处理。

## 批量安装配置

所有选中资源共用一套安装配置：

- 目标范围：项目或全局。
- 目标项目：范围为项目时必填。
- Agent：可多选，至少选择一个。
- 安装方式：复制或软链接。

批量安装会为每个“资源 × Agent”组合生成一个单资源计划。例如选择 4 个资源和 3 个 Agent 时，应生成 12 个计划。

安装弹窗默认目标规则延续单资源安装：存在项目时默认选择第一个项目；用户可显式切换到全局。安装方式和 Agent 选择统一应用于本批次全部资源，不提供逐项覆盖。

## 批量操作架构

新增独立的 `BatchOperationStore`，职责包括：

- 保存本批次资源快照和操作类型。
- 保存安装场景的统一目标配置。
- 执行资格校验并生成全部单资源请求。
- 并发生成操作计划并聚合路径、警告和错误。
- 串行执行计划，维护当前项、总体进度和结果分组。
- 取消当前计划并把剩余计划标记为未执行。

现有 `OperationStore` 继续只负责单资源操作。批量 Store 复用相同的请求构造约定，但不通过单资源 Store 间接调用，避免两个 UI 生命周期互相覆盖。

Core、preload 和 IPC 不增加批量专用接口。批量 Store 继续调用：

- `window.xcSkills.operations.inspectSourceConflict`
- `window.xcSkills.operations.plan`
- `window.xcSkills.operations.execute`
- `window.xcSkills.operations.cancel`
- `window.xcSkills.operations.onProgress`

这样可以让 Core 的受管实体、软链接、冻结和卸载规则保持唯一实现。

## 计划阶段

批量操作分为资格校验、计划生成和最终确认三个门槛：

1. 选中资源全部通过共享资格校验。
2. 为全部请求完成来源冲突检查和计划生成。
3. 用户查看汇总并明确确认。

任意请求出现来源冲突、目标占用、旧版安装记录、缺少受管实体或其他计划错误时，整个批次禁止进入执行阶段。弹窗按资源展示失败原因；用户需要退出批量操作并处理问题。本次不提供“批量替换来源”，避免一次确认覆盖多个来源不一致的目标。

计划预览展示：

- 资源数量、Agent 数量和计划总数。
- 目标范围、目标项目和安装方式。
- 受影响路径，可折叠查看完整列表。
- Core 返回的警告，按资源归组。
- 不符合或计划失败的资源及原因。

## 执行与取消

计划按照资源当前列表顺序执行；同一资源的 Agent 顺序遵循设置中的 Agent 顺序。

执行状态包含：

- `pending`：尚未执行。
- `running`：当前正在执行。
- `completed`：执行成功。
- `failed`：首个失败项。
- `cancelled`：用户取消的当前项。
- `not_run`：因失败或取消而未执行。

进度区展示总体进度和当前资源，例如“正在处理 3/12：auto-type-mapper · Claude Code”。

首次失败后立即停止，不执行后续计划，也不回滚已完成项。结果页分为“已完成”“失败/已取消”“未执行”三组，并显示每项的资源、Agent、目标路径和错误信息。

用户取消时调用当前计划的 `cancel`，等待当前执行结束为取消结果，然后把剩余计划标记为未执行。关闭执行中的弹窗需要二次确认，防止误关闭后失去进度视图。

每个成功结果立即请求重新扫描其受影响路径；批次结束后再统一刷新当前来源。刷新失败不改变文件操作结果，但会在结果页提示列表状态可能尚未同步。

## 组件与文件边界

预计新增或修改：

- `src/renderer/src/lib/asset-actions.ts`：共享单资源资格和不可用原因。
- `src/renderer/src/components/AssetList.vue`：复选框、全选和批量工具栏入口。
- `src/renderer/src/components/ResourceExplorer.vue`：选择状态的上下文清理和批量事件转发。
- `src/renderer/src/stores/batch-operation.ts`：批量计划、执行、取消和结果状态机。
- `src/renderer/src/features/operations/BatchOperationDialog.vue`：配置、预览、确认、进度和结果界面。
- `src/renderer/src/App.vue`：挂载批量弹窗并传入来源、项目和 Agent 上下文。
- 相关 renderer 单元与组件测试。

如果实现时发现共享请求构造发生重复，可提取小型纯函数；不借此重构 Core 或单资源操作状态机。

## 错误处理

- 资格错误：在打开弹窗前阻止，展示全部不合法项。
- 计划错误：保留已成功生成的计划仅供诊断，但禁止执行整个批次。
- 执行错误：记录首个失败项，停止后续执行，保留已成功结果。
- 取消错误：展示取消失败原因；若原计划仍在执行，保持执行状态而不是假报取消成功。
- 刷新错误：结果页给出单独警告，不把已经完成的文件操作标记为失败。

错误信息优先展示资源名和 Agent 名，技术路径与原始错误放在可展开详情中。

## 测试策略

### 纯函数测试

- 各来源和状态的单资源可用操作。
- 冻结、解冻、卸载的逐项不合法原因。
- 全部合法与混合状态的批量资格结果。

### Store 测试

- 批量安装按资源数和 Agent 数生成正确请求。
- 冻结、解冻和卸载使用各资源的精确安装位置。
- 任一计划失败时禁止执行。
- 串行顺序、首错停止和未执行分组。
- 取消当前计划并停止后续执行。
- 成功项路径刷新和批次结束刷新。

### 组件测试

- 当前筛选结果的三态全选。
- 搜索、筛选、来源和类型变化时清空选择。
- 严格资格校验下按钮禁用及原因展示。
- 批量安装统一配置和计划汇总。
- 执行进度、失败结果和取消交互。
- 现有单行详情与操作入口不受影响。

### 完整验证

- `pnpm test`
- `pnpm typecheck`
- `pnpm build`
- 对资源选择、批量安装、批量冻结、批量解冻和批量卸载进行 Electron 手工验证。

## 验收标准

1. 用户可以勾选单项或全选当前筛选结果。
2. 中央和第三方仓库可批量安装；项目和全局列表可批量冻结、解冻和卸载。
3. 任意选中项状态不符合时，对应批量操作整体禁止并显示具体原因。
4. 批量安装对全部资源使用同一目标配置。
5. 所有计划生成成功后才能确认执行。
6. 执行严格串行，首次失败或取消后停止剩余计划。
7. 结果明确区分已完成、失败/取消和未执行项。
8. 单资源操作、详情抽屉和现有受管资源语义保持不变。
