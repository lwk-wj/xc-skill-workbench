# 扁平安装目录状态识别修复设计

## 问题

中央仓库资源保留分组，例如 `backend/skills/call-api`；安装到 Agent 后使用平台原生扁平目录，例如 `.codex/skills/call-api`。项目扫描因此得到空分组。当前状态服务要求 `type + group + name` 完全一致，并按 `root/group/name` 构造安装位置，导致已成功安装且内容一致的资源被标记为“未知”或“未安装”。

## 设计

- 保持现有安装布局，不改变用户项目目录结构。
- 中央仓库详情页检查安装位置时使用与安装计划一致的 `root/name`。
- 已安装资源回查中央仓库时：先按 `type + group + name` 精确匹配；当安装项分组为空时，按 `type + name` 查找唯一候选。
- 若按 `type + name` 找到多个跨分组同名候选，不猜测来源，返回明确的“中央仓库存在多个同名资产”未知状态。
- 更新操作复用同一匹配规则，避免状态能识别但更新仍找不到源资源。

## 验证

- 回归测试覆盖中央资源带分组、项目安装项为空分组的场景。
- 断言状态评估使用实际扁平安装路径，并返回当前版本。
- 断言中央详情页生成的全局与项目位置均不包含仓库分组。
- 运行主进程测试、完整测试、类型检查和构建。
